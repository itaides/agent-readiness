# Design handoff — agent-readiness web UI

Handoff for a Claude design session. Goal: a visual direction + component spec for a web surface for `agent-readiness`, using **hosted agent-readiness scoreboards** as the primary reference and our existing `--format html` report as the baseline to replace.

## Context

`agent-readiness` is a Bun/TypeScript CLI that scans any URL (incl. localhost) for AI-agent readiness. It emits a JSON report (`--format json`) consumed by CI and an HTML report (`--format html`) humans read. The product now has a 0–100 score with letter grade, a 5-category check taxonomy, per-check remediation text + verify commands, and a `--crawl` mode that aggregates page-level checks across sampled sitemap URLs.

## Reference: hosted scoreboards (what to take, what not)

Hosted agent-readiness scoreboards ("make your site work for agents") do these well:

- **Score as hero.** One number + letter grade dominates the page (`42/100`, `A+`). Big, unmissable, color-coded. Adopt this.
- **Benchmark framing.** "117,739 sites scanned · average rank 42 · 5% rank B or above" — instantly tells you if your score matters. Adopt the pattern once we have aggregate data; design a slot for it now (can show "n checks passing" until then).
- **Category leaderboards** ("Agent Tools: ZenRows 96 A+, Acme 94 A…"). A right-rail or below-fold table of well-known scores. Take the table style; data is aspirational.
- **"Watch an agent try your site" (Journey).** A timeline: intent → steps → searches → issues. Design the component; our CLI doesn't produce journey data yet — spec it as an optional card that renders only when `report.journey` exists.
- **Terminal parity.** "The same scan, from your terminal" — CLI is a first-class citizen. Keep install/usage copy visible.

Do not take: signup gates before results, animated scanning theater that delays real output, leaderboards we can't back with real data.

## Data the UI renders

`Report` JSON (see `src/types.ts`): `target`, `scannedAt`, `summary` (per-category pass/fail/total), `checks[]` (id, category, title, status pass|fail|warn|skip, message, evidence, remediation {suggestion, verifyCommand}, remediationPromptPath), `score {value, grade, passed, total}`, optional `crawl {pages[], perCheck{pass,warn,fail}}`.

## Deliverables

1. **Report page** (replaces `--format html`): single self-contained HTML file, inline CSS/JS, no external requests (hard requirement — it goes into CI artifacts and PR comments), light + dark mode via `prefers-color-scheme`, printable.
   - Hero: score ring or bar, letter grade, target URL, scan timestamp.
   - Category strip: 5 cards (discoverability, content, bot-access, capabilities, commerce) with pass/total.
   - Check list grouped by category: status badge, title, message, expandable evidence, remediation block ("How to fix" + verify command, copy button).
   - Crawl section when `report.crawl` exists: per-check pass-rate table over sampled pages.
   - Footer: generator + spec links.
2. **Landing/scan page** (future hosted UI): URL input → score hero → same report components. Show the CLI install command prominently ("the same scan, from your terminal").
3. **Component inventory** for the report: status badge (PASS/FAIL/WARN/SKIP), score ring, category card, check row with `<details>` evidence, remediation callout, crawl table, journey card (spec-only).

## Constraints

- Self-contained single file for the report — inline everything, no fonts/CDN/images.
- Monospace accents for URLs/commands; statuses must be readable in both themes (current palette: pass `#16a34a`, fail `#dc2626`, warn `#ca8a04`, skip `#6b7280`, accent `#2563eb` — refine but keep the 4-status semantics).
- Content is dynamic: check titles/messages vary, evidence is arbitrary JSON, remediation may be absent. Components must degrade gracefully.
- Print stylesheet: badges and callouts must survive printing for PDF-in-CI workflows.
- The report file is generated by `formatHtml` in `src/report.ts` — ship a spec the implementer can map to that template (HTML structure + CSS), not a runnable app.

## Open questions for the design pass

- Grade display: plain "A" vs. ring-with-grade hybrid — pick one.
- Should warns count visually toward score? Recommendation: show score by scored checks only, list warns separately (matches semantics).
- Where does the "what is agent readiness" explainer live on the landing page vs. a docs link.
